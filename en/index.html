Fleet Management System

in use · continuously improved
Open demo ↗Code ↗
period
2026 – presentoldest record: Jun 18, 2026
goal
Centralize a whole department's controls and stop depending on spreadsheets
my contribution
Requirements, workflow design, development, maintenance and improvements

problem

The department's controls lived in separate spreadsheets. Merging data was manual, deadlines depended on someone checking, and each item's history was scattered.

solution and features

  • One platform with a module per process.
  • Automatic expiry alerts and calculated status.
  • Each item's full history on one screen.
  • Fuel efficiency indicator (km/L) from the monthly fueling report.
  • PDF and Excel reports, recycle bin with restore and a change log.
  • Old records migrated from spreadsheets and PDFs.

results

All the department's information in one place, a record of who changed each entry and monthly reports generated by the system itself.

04 / featured personal project

ORION: from a plain-language request to a working system

ORION is where I take automation one step further: instead of building each system by hand, I'm building the assistant that builds them.

in development · since Oct 7, 2026 (documented stage)

An AI assistant for Windows that creates and maintains systems

From a request like “build a complete fleet management system”, ORION defines the structure, generates the code, tests the result and runs the system on the computer. After that it takes changes through conversation (“add field X”, “create a Y report”) and keeps every version.

  • Voice and textPlain-language commands, with speech recognition and synthesis.
  • Swappable AIVendor-independent design, including local models.
  • Automated testsEvery version is checked before delivery.
  • Versions and migrationsSchema history and database migration scripts.
  • Decision memoryKeeps each project's goal, decisions and history.
  • Protected spaceCustom code in custom/ is never overwritten.
